# M1 evaluation harness

`python -m Ai.evaluation.evaluate --controllers fixed rule rl --seed-set dev` runs the M1 development block. `--seed-set final` selects the reserved final block for T3.2; it is not run during T3.1. `--jobs auto` (the config default) or a positive `--jobs` value controls concurrency. The harness prepares each scenario/seed route once with `ScenarioBuilder.ensure_routes()` and records its SHA-256 in each run's `evaluation.json`. It uses only the pinned validation-best PPO checkpoint; a missing or failed PPO load stops the RL grid rather than silently evaluating fallback behavior as PPO.

The run grid covers seven configured scenarios, five seeds per selected block, and each requested controller. A completed cell is reused only when `run.json`, `summary.csv`, `steps.csv`, `trips.csv`, and matching evaluation metadata exist. Interrupted or malformed outputs are preserved and not counted as complete; rerunning the same command fills missing cells. Controller runs use identical cached route bytes for each scenario/seed. Raw episode directories are never overwritten.

## Aggregation

`results/summary/comparison.csv` is rebuilt from lineage-checked M1 evaluation runs in `results/raw/` for both dev and final seed sets. The file follows the Section 11 column schema. Per-scenario rows are accompanied by:

- `headline`: an unweighted average over `balanced`, `directional_ns`, `directional_ew`, `medium`, `heavy`, and `rush_hour`; `low` is excluded.
- `primary`: an unweighted average over `medium`, `heavy`, and `rush_hour`.
- `low`: the separate low-demand result.
- `pooled`: a trip-weighted sensitivity result, with completed-trip counts summed per seed and per-episode queue/congestion measures averaged.

Metric A uses all scheduled trips; metric B uses trips whose cached route contains a TLS-controlled movement. `trip_basis=common` uses the intersection of vehicle IDs completed by every included controller on that exact scenario/seed route. `trip_basis=all` reports censored time, with unfinished trips counted through the common simulation end, and includes completion rates, completed/unfinished counts, waiting and time loss. Queue, throughput, congestion, and teleports use junction scope. Values in `mean` and `std` are computed over seed-level values; improvement is `(fixed − controller) / fixed` for lower-is-better metrics and `(controller − fixed) / fixed` for higher-is-better metrics. Improvement metric rows carry the paired bootstrap 95% confidence intervals over the per-seed paired improvements. A zero reference with a nonzero candidate has no defined percentage and is left blank rather than emitted as infinity or NaN.

`target_met` is calculated for RL travel time against `eval.target_reduction_pct` separately by aggregation, scope, and common/censored basis. The CLI prints these outcomes and states when common-trip and censored results disagree. Completion-rate gaps over `eval.completion_gap_flag_pp` are flagged as possible survivorship bias.

The harness writes simulated figures under `results/figures/`: common-trip and censored travel time, completion rate, waiting time, queue, throughput, and per-scenario paired travel-time improvement with confidence error bars. Re-running with the same complete artifacts rebuilds the aggregate deterministically; no model or route is retrained or promoted.

## M2 network development evaluation (T4.8)

`python -m Ai.evaluation.evaluate --family network --controllers fixed rule rl --seed-set dev` runs the five frozen network scenarios (`net_balanced`, `net_low`, `net_medium`, `net_heavy`, `net_rush_hour`), five dev seeds (5000–5004), and three controllers (75 cells). Final seeds are rejected in this mode and remain reserved for T4.9. Routes are prepared once with the network `ScenarioBuilder`; the evaluator does not rewrite the existing per-scenario `.sumocfg` files. All controllers read the same route bytes for a scenario/seed.

RL is pinned by the network harness to `Ai/rl/models/ppo_net_v2_rejection_penalty_005/evaluations/best_model.zip` with expected SHA-256 `758711e7f28e29e69b59af6eade30ba679c3160daadf39e09ed89287f5037757`. This is the accepted T4.7 candidate. The shared `rl_net.model_path` still names the older checkpoint, so the network harness deliberately overrides it in an in-memory evaluation config. It refuses a missing, corrupt, metadata-incompatible, or hash-mismatched candidate; there is no fallback-only run mislabeled as PPO.

A network cell is reused only when its five raw episode files and `evaluation.json` are nonempty and valid; family, scenario, seed, controller, route file/hash, project config hash, controller-config hash, checkpoint path/hash, summary/trip lineage, all 12 intended TLS rows, finite required metrics, and PPO tick-share bounds match the current evaluation. Partial outputs are preserved but are not skipped. Fixed/rule cells from validation seeds 3000–3002 are not substitutes for development seeds. Each cell receives a unique raw directory; an interrupted attempt is preserved and a later invocation fills only missing cells.

Network raw `evaluation.json` records route/config/controller hashes and exact model identity. `results/summary/network_runs.csv` records per-cell coverage, common-trip counts, completion, censored travel time, fallback-owned tick share, safety counters, inference latency, wall time, route lineage and model identity. `network_junctions.csv` reports per-scenario/per-controller queue, wait, congestion share, tick ownership/fallback, safety counters, and coverage classification. The simulated heatmap is `results/figures/network_junction_congestion.png`.

M2 `comparison.csv` rows use Metric N (all network trips). Completed common trips are primary; censored all-scheduled-trip travel time, completion rates, common-trip counts, and pooled-trip sensitivity remain alongside it. Improvement is `(fixed − rl) / fixed × 100` for travel time. The headline averages seeds within each scenario and then equally averages the four non-low scenarios; `net_low` is separate, and the three primary scenarios have their own rows. `target_met` is computed from the configured 10% threshold and actual values. Existing M1 comparison rows are preserved when M2 rows are rebuilt. The run summary calculates `ai_coverage` using `eval.ai_coverage_min_share` (0.95 per intended TLS); `1 - ppo_tick_share` exposes fallback ownership. The prior T4.7 gate's 57.74% fallback share is therefore reported as a reliability risk and does not imply ≥95% PPO ownership per TLS.

T4.8 pre-run serial estimate uses saved T4.4 and T4.7 wall-clock measurements: 30 fixed/rule baseline cells and six accepted-candidate RL cells project about 21,696 seconds (6.03 hours) for 75 episodes, excluding route generation and startup. Auto scheduling probes one heavy network cell and measures SUMO RSS before selecting worker count from available RAM. No training is part of T4.8.

T4.8 dev run completed in job `20261101-130401_d0dddfe6` (75/75 valid, RC 0) in 2 h 22 min 53 s with four auto-selected workers. Actual output metrics, the target result, fallback/coverage caveat, and reproducibility hashes are recorded in `docs/results.md` Part 2 and `docs/experiment_log.md`. The 23.35% development Metric N improvement is not a final-seed result; all 25 RL cells report `ai_coverage=none` at the configured 0.95 per-TLS PPO share.
